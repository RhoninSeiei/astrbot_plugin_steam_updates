# Steam 公告图上方间距设计

## 背景

2026 年 8 月 10 日 17:15 生成的游戏更新卡片中，公告正文最后一行的可见像素结束于 `y=1545`，公告图从 `y=1546` 开始，两者之间没有背景空白行。现有 `RenderBlock.gap` 表示块结束后的间距；公告图片块设置的 `gap=10` 仅作用于图片下方，无法保证图片上方留白。

本次修改仅处理普通游戏公告图上方的视觉间距，保持其他文字行距和图片类型的排版不变。

## 目标

普通游戏公告的每张公告图上方保留 16 像素空白。公告原图和固定游戏图回退采用相同规则。现有公告图限宽、等比缩放、水平居中、完整展示和无图回退行为保持不变。

## 设计

在渲染常量区域增加：

```python
NEWS_IMAGE_TOP_MARGIN = 16
```

在 `RenderBlock` 数据结构末尾增加默认字段：

```python
top_gap: int = 0
```

字段放在末尾，以保持现有位置参数调用兼容。默认值为 0，使既有文本块、创意工坊图片、免费游戏图片和其他页眉图片维持当前排版。

`_draw_blocks()` 在绘制图片前先增加 `top_gap`，再计算水平位置并粘贴图片。`_measure_blocks_height()` 对图片块计入相同的 `top_gap`。绘制坐标与卡片总高度由同一规则计算，避免图片或页脚超出画布。

`_build_section_blocks()` 仅在普通游戏公告分支生成公告图片块时设置 `top_gap=NEWS_IMAGE_TOP_MARGIN`。该设置同时覆盖有效公告原图和固定游戏图回退。创意工坊、免费游戏及其他图片块继续使用默认值 0。

## 数据处理过程

1. 每条普通游戏公告完成标题和摘要文本块构建。
2. 图片候选下载成功时选择第一张有效公告图；缺失或失败时选择对应固定游戏图。
3. 图片按照现有规则限宽并保持原始比例。
4. 图片块携带 16 像素 `top_gap`，绘制时先保留空白，再水平居中粘贴。
5. 高度测量同步增加 16 像素，卡片像素预算继续保护超长卡片。

## 兼容性

每条带图的普通游戏公告会使卡片高度增加 16 像素。超长卡片可能更早达到现有像素预算并改用文本发送，这是既有保护机制的预期行为。

配置结构、UMO 通知、旧群号字段、状态文件和图片缓存格式均保持不变。该修改无需新增配置项，也无需迁移现有配置。

## 测试

在 `tests/test_news_images.py` 中增加或扩充以下测试：

1. 构造带 `top_gap=16` 的图片块，验证图片前 16 行保持背景色，图片从第 17 行开始绘制。
2. 验证 `_measure_blocks_height()` 计入 `top_gap + image.height + gap`，并与 `_draw_blocks()` 返回的最终坐标一致。
3. 验证公告原图与固定游戏图回退生成的图片块都使用 `NEWS_IMAGE_TOP_MARGIN`。
4. 验证默认图片块的 `top_gap` 为 0，现有水平居中和完整高度测试继续通过。
5. 运行全部 76 项现有测试及新增测试，并生成一张代表性卡片进行像素检查。
