## 调研依据

1. AstrBot 原生配置 schema 支持 template_list，可用列表条目展示一个会话的配置，无需新增前端构建链。
   https://github.com/AstrBotDevs/AstrBot/blob/master/docs/zh/dev/star/guides/plugin-config.md
2. Soulter/astrbot_plugin_bilibili：当前会话订阅使用 event.unified_msg_origin；跨会话订阅、删除及列表是独立管理员命令；额外提供 Plugin Page。
   https://github.com/Soulter/astrbot_plugin_bilibili/blob/master/main.py
3. Soulter/astrbot_plugin_rss：rss 命令组提供 add/list/remove；列表和删除限定当前 UMO。
   https://github.com/Soulter/astrbot_plugin_rss/blob/master/main.py

只借鉴交互和职责划分。其他项目的 UMO 字符串切分、默认权限或存储实现不直接照搬。

## 订阅模型与兼容语义

新增 subscription_settings.sessions 原生 template_list，每个 UMO 最多一条有效规则：

| 字段 | 含义 |
| --- | --- |
| label | 可选备注，用于配置条目标题，不参与寻址 |
| umo | AstrBot MessageSession 解析并规范化的完整会话标识 |
| enabled | 是否接收自动推送；关闭时不能落回旧全局配置 |
| steam_appids | 该会话独立游戏列表；空列表表示不订阅游戏 |
| workshop_item_ids | 该会话独立创意工坊列表；空列表表示不订阅创意工坊 |
| free_games_mode | inherit/on/off，继承全局开关、开启或关闭免费领取推送 |
| message_mode | inherit/card/text，继承全局模式或覆盖 |

- 第一版不加入每群独立模型、代理、语言、字体、轮询周期或任意过滤表达式。
- 全局 enable_push 仍为总开关；workshop_enable 和 free_games_enable 的现有角色需写清：建议保留为全局功能总开关，单群设置只控制是否接收，不能绕过总开关。
- 无显式规则的旧 notify_umos/notify_group_ids 目标沿用旧全局订阅；不在旧列表且无显式规则的会话不接收推送。
- 显式规则完整替换该 UMO 的旧目标订阅，不与全局 AppID/条目列表暗中取并集。
- 命令首次修改旧目标时，将其当前生效订阅复制为显式规则，再增删；新目标从空订阅开始，免费领取默认关闭。
- 取消最后一个订阅仍保留空的显式规则；暂停保留 enabled=false。删除整个规则表示恢复旧配置继承，必须单独命名并明确提示。
- 重复 UMO、非法 ID 和非法模式保存时拒绝；手工写入的重复规则按该 UMO 整体拒绝执行并告警，避免静默择一或广播。
- 不使用群号作为订阅主键；不同平台实例中相同群号必须隔离，兼容消息类型与带冒号的会话 ID。

## 界面与命令

优先使用上游已有分组式配置，在“分会话订阅”中通过原生模板条目增删改查；显示备注、完整 UMO、订阅列表、免费领取开关及展示模式。第一版不增加独立 Plugin Page。

新增中文命令组 STEAM订阅，英文入口 steam_sub 作为别名；参数示例：

```text
/STEAM订阅 列表
/STEAM订阅 添加 游戏 730 570
/STEAM订阅 删除 游戏 730
/STEAM订阅 添加 创意工坊 123456789
/STEAM订阅 免费领取 开启
/STEAM订阅 模式 图片
/STEAM订阅 暂停
/STEAM订阅 恢复
```

- 默认只作用于 event.unified_msg_origin，普通调用不能通过参数覆盖目标。
- 保留 STEAM更新、创意工坊更新与 steam_update_ping；旧查询命令按当前会话生效订阅查询，不返回其他会话订阅。
- 独立管理员入口 STEAM全局订阅 支持指定完整 UMO；带空格的 UMO 支持引号或中文括号，解析后仍由 MessageSession 验证。
- 返回新增、已存在、已删除、未订阅等明确结果；不使用易随排序变化的索引作为唯一删除参数。
- 配置和命令使用同一校验及订阅解析层；命令通过 AstrBot 配置对象的保存机制写入同一配置字段，不另外维护一份 subscriptions.json。
- 命令读改写使用插件级异步锁，保存失败不先发布内存结果；WebUI 按 AstrBot 原生保存/重载语义生效。原生界面的旧表单整表覆盖风险不能宣称已由插件锁解决，实施时核查核心配置保存接口及冲突策略。

## 已确认权限

确认采用：查看本会话订阅允许普通成员；修改由 AstrBot 管理员或已验证的本群群主/管理员执行；跨 UMO 管理仅 AstrBot 管理员。

- 群角色必须来自适配器提供的可信事件信息，不以昵称、正文或自行声明的角色判断。
- 适配器不能可靠提供群角色时，限制为 AstrBot 管理员；禁止猜测权限。
- 私聊第一版默认只有 AstrBot 管理员可修改，避免意外开放公共订阅服务。
- 在处理函数内校验权限；不能把 bot-admin 装饰器与群管理员条件简单叠加，造成允许范围错误。
- 适配器群信息查询使用 AstrBot 的 get_group 接口校验群 ID、群主和管理员 ID。

## 轮询与状态

1. 读取一次有效订阅快照，解析每个目标的来源集合。
2. 对所有有效目标取游戏/创意工坊查询并集；每个来源每轮抓取一次，共享现有并发限制。
3. 根据每个目标的订阅和投递状态选择待发公告；查询失败占位也只发给订阅该来源的目标。
4. 相同内容和展示参数复用整理及渲染结果；先选择内容再拼卡片，避免先发送所有游戏再在文字层过滤。
5. 以完整 UMO + 来源类型 + 来源 ID 记录状态；扩展上游 v1.3.5+ 的游戏目标状态，将创意工坊与免费领取也纳入独立投递状态。
6. 成功只推进对应目标；明确失败保留重试；结果不确定按上游 v1.3.7 语义记录并抑制重复。
7. 旧目标迁移优先使用上游已有目标状态，其次使用旧全局状态作为初始基线；首次迁移持久化完成后再发送，保留原文件备份。
8. 新增来源默认建立基线，不补推历史公告；用户可通过现有查询命令主动查看。首次抓取失败不建立虚假的空基线，等待下一次成功。
9. 重新订阅保留已见状态；暂停期间不追赶历史积压，恢复时对新增公告建立明确基线；免费领取保持“新活动独立提醒、活跃活动可附带”的上游语义，但按目标分别判断。
10. 发布前重新校验订阅快照，避免刚退订仍发送；外部发送已在进行时不能保证撤回，需明确这条边界。

- 从最新上游 0d0d013 建立独立开发分支，PR 不从本地长期维护分支直接发起。

## 实施与验收顺序

1. 确认权限政策及上游兼容最低版本；固定上游提交，在隔离分支实现。
2. 先定义 subscription resolver 和迁移回归用例，再接原生配置与命令。
3. 扩展按目标投递状态，拆分数据获取、内容选择和发送；确保不修改全局 self.config 来临时模拟某群设置。
4. 用至少三个 UMO 验证交叠订阅、不同平台同群号、空订阅、暂停和继承；验证查询并集只抓取一次。
5. 覆盖全部成功、部分失败、结果不确定、首次抓取失败、迁移重启、重新订阅、取消时共享任务、并发命令保存失败及越权请求。
6. 验证游戏、创意工坊、免费领取三条主流程；检查 LLM 缓存键和渲染缓存键不会串群。
7. 在隔离 AstrBot 环境验证原生配置条目、保存重载及命令反馈；不向真实群发送开发测试消息。
8. 完成差异审查与完整测试后推送中文 PR，描述兼容策略、验证范围和限制；不沿用旧版本“两星期验证”的说法。
9. 之后在本地维护分支合入同一功能并重放独有修复，另行执行生产发布验收。
